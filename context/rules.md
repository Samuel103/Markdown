# Project rules

## Code

- Respecter React, TypeScript, Vite et Tailwind existants; garder les composants et API ciblés.
- Préserver les changements non liés et valider proportionnellement (`lint`, tests ou build disponibles).
- Avant de créer une abstraction réutilisable (composant, hook, helper, type partagé, état, utilitaire, pattern CSS/Tailwind, client ou validateur), consulter `reuse-scout` et suivre sa recommandation : `REUSE`, `EXTEND` ou `CREATE`.
- Le scout est inutile pour documentation, correction typographique, configuration, modification évidente d'une ligne, ou assertion de test sans comportement réutilisable.

## Produit

- Le projet reste un éditeur Markdown simple : écrire, prévisualiser, sauvegarder.
- Favoriser simplicité, rapidité, minimalisme, clavier, responsive et maintenabilité.
